# Milestones

All milestones below are **proposed**, not completed or awarded. The plan is ordered by dependency rather than invented calendar dates. Continuing maintenance is not an unlimited service commitment to the funder.

## 01 / Distribution baseline

Configure production signing, secure the project identity and verify the actual packaged candidate. Preserve preview labels until the relevant checks succeed.

**Evidence:** source revision, hashes, signing/notarization results and installation notes. A successful compiler exit is not sufficient.

## 02 / Independent security round

Agree the researcher scope and payment terms, run a focused automated pass, invite outside examination and validate findings. Prioritize remediations before expanding the feature surface.

**Evidence:** scope, findings disposition, fixes and regressions. If no eligible findings arrive, document the outcome and seek funder agreement before reallocating the reserve; spending it is not itself success.

## 03 / Packaged platform validation

Exercise the exact candidate on macOS, Windows and Linux, including installation, private-session behavior, browser interactions and shutdown.

**Evidence:** a matrix naming operating system, hardware, artifact hash, test procedure and result. Unknown stays unknown.

## 04 / CEF investigation

Create the initial source-build environment, test the narrow extension hypothesis, and decide whether a maintained patch is justified.

**Evidence:** recipe, patch where applicable, compatibility matrix, failed approaches and measured maintenance cost. A rigorous negative result closes this milestone.

## 05 / Closeout

Publish an expense and outcomes record, remaining obligations and open limitations. Signing and domain renewals remain visible as future obligations, even when funds have been reserved for them.

**Evidence:** amount allocated, spent and remaining per category; public work produced; any funder-approved reallocation. Do not publish researchers' personal payment details.
